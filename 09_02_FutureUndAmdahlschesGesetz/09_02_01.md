- `Future { ... }` 启动后，会在一个后台线程中异步运行。
- `Thread.sleep(2000)` 模拟了这个异步任务耗时 2 秒。
- 2 秒后，这个 `Future` 完成，结果为 `42`，并保存在 `Future` 对象中。
- 但由于你**没有任何地方使用这个结果**，比如 `println` 或者 `onComplete`，所以程序虽然等了 10 秒后退出了，但你并不会看到任何输出。

4. Mittels Await kann auf das Ergebnis eines Futures gewartet werden. Was ist ein Nachteil aus sicht der Asynchronen Berechnung von Await?

Await.result(future, timeout) blockiert den aktuellen Thread, bis das Ergebnis vorliegt oder das Timeout erreicht ist.
Nachteil: Es verhindert echte Asynchronität, da der Thread während des Wartens blockiert wird und somit nicht für andere Aufgaben zur Verfügung steht. Das widerspricht dem Sinn von nicht-blockierender, asynchroner Programmierung.

好的，我们可以使用 Await 来同步等待一个 Future 的结果。但是请注意，Await 会阻塞当前线程，这违背了异步编程的初衷，通常只在测试或快速原型中使用。

```scala
import scala.concurrent.{Future, Await, ExecutionContext}
import scala.concurrent.duration._
import scala.util.{Success, Failure}

class Grundlagen {}

object Grundlagen {
  def main(args: Array[String]): Unit = {
    // 引入默认的 ExecutionContext（线程池）
    import ExecutionContext.Implicits.global

    // 创建一个异步计算，延迟2秒后返回 42
    val future: Future[Int] = Future {
      Thread.sleep(2000)
      42
    }

    // 使用 Await 等待 Future 的结果（最多等待5秒）
    try {
      val result: Int = Await.result(future, 5.seconds)
      println(s"Ergebnis mit Await: $result")
    } catch {
      case ex: Exception => println(s"Fehler beim Warten: ${ex.getMessage}")
    }
  }
}

```

5. Angenommen Sie haben einen Future gestartet, welcher eine Zeitintensive Berechnung ausführt. Der Elternprozess kann aber nicht länger als 10 Sekunden auf die Berechnung warten, da diese sonst irrelevant wird. Wie können Sie sicherstellen das kein veraltetes Ergebnis verwendet wird?

```scala
import scala.concurrent._
import scala.concurrent.duration._
import scala.util.{Success, Failure}

val longCalc: Future[Int] = Future {
  Thread.sleep(20000) // lange Berechnung 这个 `Future` 表示一个**耗时 20 秒**的“长计算”，最后返回 `42`。
  42
}

val timeout = Future {
  Thread.sleep(10000)
  throw new TimeoutException("Timeout nach 10 Sekunden")
}

val result = Future.firstCompletedOf(Seq(longCalc, timeout))

result.onComplete {
  case Success(value) => println(s"Ergebnis: $value")
  case Failure(ex)    => println(s"Fehler: ${ex.getMessage}")
}

```

- `Future.firstCompletedOf(...)` 会**返回两个 Future 中先完成的那个的结果**。
- 也就是说：
    - 如果 `longCalc` 在 10 秒内完成，则它的结果 `42` 会被使用。
    - 如果超时的 `timeout` 先完成（也就是 10 秒后触发），那么程序就会认为**超时失败**。

| 时间  | 事件                         |
| --- | -------------------------- |
| 0s  | 两个 `Future` 同时启动           |
| 10s | `timeout` 抛出异常，`result` 完成 |
| 20s | `longCalc` 才完成，但不再被使用      |

## 2.1 Scala 的 Future 需要一个 ExecutionContext

`Future` 本身只是一个容器，表示“将来某个时刻会有的结果”。  
但 **要让它实际运行任务（代码块）并产生结果，就必须把它交给某个“执行者”去调度和执行。**

这个“执行者”就是 **`ExecutionContext`** —— 它负责：
- 分配线程来执行你的任务
- 决定任务在哪里、何时、怎样运行

可以把 `Future` 比作一个“快递单”：
- 你写好了快递单（代码块），但它只是个说明，还没真正运送。
- `ExecutionContext` 就像是快递公司，它安排快递员（线程）来实际完成投递（执行任务）。

如果没有快递公司（没有 ExecutionContext），这个单子永远不会有人处理。


---


`Future` 的源码大致是这样的（简化）：
```
object Future {
  def apply[T](body: => T)(implicit ec: ExecutionContext): Future[T] = {
    val p = Promise[T]()
    ec.execute(new Runnable {
      def run(): Unit = p.success(body)
    })
    p.future
  }
}

```


- `body` 是你传进去的代码块
- `ec.execute(...)` 会启动一个线程来执行它
- 没有 `ExecutionContext`，就没法 `execute`

- 它基于 `ForkJoinPool`，适合大多数简单场景

# 3 Futures – Composites

- Scala 的 `Future` 和其 `.map`/`.flatMap`/`.onComplete` 都是**异步非阻塞**的。
- 每一步都通过 `ExecutionContext` 被调度到线程池中的某个线程运行。
- 默认线程池可以并发执行多个步骤，但不保证在线程上连续执行。
- 如果你想强制所有步骤只用一个线程，可以使用你自己定义的 `ExecutionContext`（例如基于 `Executors.newSingleThreadExecutor`）


```
val result = Future { 10 }
  .map(_ + 5)
  .map(_ * 2)

result.onComplete {
  case Success(value) => println(s"Result: $value")
  case Failure(ex)    => println(s"Error: ${ex.getMessage}")
}

```

![](image/Pasted%20image%2020250714215435.png)

**最多可能用 4 个线程，但通常由于线程池复用，实际线程数可能是 1~4 个。**

| 步骤              | 说明                                  | 所在线程                                                                           |
| --------------- | ----------------------------------- | ------------------------------------------------------------------------------ |
| `Future { 10 }` | 异步计算启动                              | Thread-1                                                                       |
| `.map(_ + 5)`   | 第一次变换                               | Thread-2 (或 Thread-1)  **可能会在另一个线程中执行（如 Thread-2）**，也可能被优化为在当前线程内完成（视线程池调度器实现） |
| `.map(_ * 2)`   | 第二次变换                               | Thread-3 (或复用上一步)                                                              |
| `onComplete`    | 回调打印结果. 注册一个回调函数，当整个 Future 链条完成后执行 | Thread-4 (或复用上一步)   . 回调本身也会在 `ExecutionContext` 管理的线程中运行                      |


## 3.1 **复用上一个线程**

如果满足以下条件，可能复用同一线程：

1. 上一个 `Future` 完成时，该线程仍然可用。    
2. 线程池没有抢占或者调度别的任务。
3. `map` 使用的是 **当前上下文的 ExecutionContext**。
4. 有时 JVM 优化会短路调度流程（特别是计算很快时），直接在当前线程完成任务。
💡 如果你打印线程名，会发现小计算往往复用前一个线程（例如三个步骤都在 `ForkJoinPool-1-worker-3` 执行）。

|条件|是否复用线程|
|---|---|
|使用默认 ExecutionContext（global）|有可能|
|任务非常快，线程空闲|有可能|
|当前 ExecutionContext 不阻塞|有可能|
|切换上下文或线程池|不复用|
|显式使用 `.map(...)(newContext)`|不复用|


# 4 Parallelisierte API-Simulation mit Futures

在分布式系统中，通常会**同时请求多个外部服务**。在这个任务中，你将使用 Scala 的 `Future` 来模拟这种**并发的 API 调用行为**。
In verteilten Systemen werden häufig mehrere externe Services gleichzeitig abgefragt. In dieser Aufgabe simulieren Sie solche parallelen API-Aufrufe mithilfe von Scala Futures.
Betrachten Sie hierzu das Objekt ParallelApiSimulation in der Vorlage. Die Methode fetchDataFromService simuliert einen API-Aufruf mit zufälliger Verzögerung sowie einer Fehlerwahrscheinlichkeit. Ihre Aufgabe ist es, diese Aufrufe für mehrere Services parallel zu starten und die Ergebnisse jeweils sofort nach ihrem Eintreffen auszugeben. 
```
def fetchDataFromService(id: Int): Future[String]
```
会模拟一次 API 调用，它具有：
- **随机的延迟**（用来模拟网络延迟）    
- **一定的失败概率**（用来模拟服务失败


Implementieren Sie dazu die main-Methode so, dass:
1. eine Liste von Service-IDs (z.B. 1 bis 10) erzeugt wird,
2. für jede ID fetchDataFromService(id) parallel aufgerufen wird,
3. Fehler einzelner Aufrufe abgefangen und eine entsprechende Fehlermeldung (z. B. "Fehler bei Service 5: ...") ausgegeben wird,
4. das Ergebnis jedes Aufrufs direkt nach dessen Abschluss in der Konsole ausgegeben wird,
5. nach Abschluss aller Futures:
    • die Gesamtdauer gemessen und ausgegeben wird,
    • der verwendete Thread-Pool korrekt beendet wird.

在 `main` 方法中完成如下功能：

1. **创建一个 Service ID 列表**，例如 `1` 到 `10`。
2. 对于每个 ID，调用 `fetchDataFromService(id)` —— 并且是**并行执行**（即并发发出所有请求）。
3. 如果某个服务失败（即 Future 失败），**捕捉异常**并输出如：  
    `Fehler bei Service 5: ...`
4. 每当某个 API 请求完成（成功或失败），**立即在控制台打印结果**（不是等全部完成之后才打印）。
5. 等**所有请求完成**后：
    - **记录并输出总耗时**；
    - 正确地关闭你使用的线程池（`ExecutionContext`）

Hinweise
• Die Fehlerbehandlung soll mit .recover erfolgen.
• Nutzen Sie Future.sequence, um zu erkennen, wann alle Futures abgeschlossen sind.
• Achten Sie darauf, dass Ihr Programm nicht vorzeitig beendet wird, bevor alle Ausgaben erfolgt sind.
• Verwenden Sie kein Await.result. Die Lösung soll nicht blockierend sein

- 使用 `.recover` 处理单个 Future 的错误；
- 使用 `Future.sequence` 检测所有 Future 是否完成；
- **不要使用 `Await.result`**，必须保证整个程序是**非阻塞的**；
- 程序不能在所有输出完成之前就退出 —— 保持主线程存活直到所有 Futures 执行完；    
- 可以考虑使用自定义线程池，并在最后显式 `shutdown()`。


| 技术 / 方法                      | 用途                                                  |
| ---------------------------- | --------------------------------------------------- |
| `Future`                     | 启动异步任务                                              |
| `.recover`                   | 捕获单个 Future 的异常并处理                                  |
| `.onComplete`                | 在单个 Future 完成时立即输出结果                                |
| `Future.sequence`            | 将 `List[Future[T]]` 转成 `Future[List[T]]`，用于等待所有任务完成 |
| `System.nanoTime()`          | 用于计算总耗时（开始/结束时间戳）                                   |
| `ExecutionContext`           | 用于控制线程池（并发执行）                                       |
| `ExecutorService.shutdown()` | 关闭线程池，释放资源                                          |

        es.shutdown() // Shutdown the ExecutorService after completion  
      case scala.util.Failure(exception) =>  
        println(s"Ein Fehler ist aufgetreten: ${exception.getMessage}")  
        es.shutdown() // Shutdown the ExecutorService even in case of failure  
    }  
  
  
    val duration: Long = System.currentTimeMillis() - startTime // error here, because the duration is calculated before the futures are completed  
    println(s"Gesamtdauer: ${duration}ms")  
  }  
  
}

Even if you set the thread pool size to 100,000,  
you won’t achieve a 100,000x speedup.  
This is because there's always a portion of the code (such as startup time, thread switching, or printing output) that **cannot be parallelized**.  
Moreover, having too many threads can introduce **scheduling overhead**, **slower context switching**, and **resource contention**.
